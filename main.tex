\section{Language}

We work with a Python-like Language (adapted from
\cite{rak-amnouykit_python_2020}). A program is made up of declarations,
statements, and expressions.\\
\[
  d_1, d_2 \Coloneq \funDecl{f}{\vv{x}}{d_1}{d_2} \mid \varDecl{x}{e}{d_1} \mid
  s
\]

\[
  s \Coloneq x = e \mid x.attr = e \mid \ifStmt{e}{s_1}{s_2} \mid
  \returnStmt e  \mid e \mid \vv{s}
\]

\[
  e_1, e_2 \Coloneq \num{n} \mid \true \mid \false \mid \dots \mid x
  \mid e.attr \mid e_1[e_2] \mid e_1(\vv{e_2}) \mid
  \listExp{e_1, \dots, e_n} \mid \dictExp{e_1: e_1', \dots, e_n:e_n' } \mid
  \newExp
\]
\\
Python's syntax does not distinguish between variable declaration, and variable
assignment, but we choose to here for simplicity. For similar reasons, we also
enforce that declarations all occur before the main body of a function or
program. Although this is not enforced by the grammar, we will assume that the
body of a function contains at most one return statement and that this will be
the last statement in the body. Any hypothetical program not following
these conventions / restrictions could be converted into a program that fits
into our grammar by a simple code transformation.

The \(\dots\) in the grammar for expressions serves as a placeholder for
a range of simple constants that are present in the language.

\section{Types}

We work with a fairly standard set of types for Python, defined by the following
grammar.
\\
\[
  A, B \Coloneq \intty \mid \boolty \mid \listty \mid
  \dictty \mid \anyty \mid \vv{A} \to B \mid [\vv{x:A}] \mid \nonety
\]
\\
The type \(\nonety\) might be expected to be related to the Python keyword of
the same name, but for our purposes it is just used as the return type for
functions that do not return a value. Our row types \([\vv{x:A}]\) are
non-standard, as they represent an upper bound on the attributes available
for an object, rather than the usual lower bound interpretation.

\begin{mathpar}
  \infer[Var]{ }{\Gamma, x:A \types x:A} \and

  \infer[Num]{ }{\Gamma \types \num{n}:\intty} \and

  \dots \and

  \infer[Dict]
  {(\forall i \in [1,n])\,\Gamma \types e_i: \anyty \\
  \Gamma \types e_i':\anyty}
  {\Gamma \types \dictExp{e_1: e_1', \dots, e_n:e_n' }:\dictty } \and

  \infer[List]
  {(\forall i \in [1,n])\,\Gamma \types e_i: \anyty}
  {\Gamma \types \listExp{e_1, \dots, e_n}:\listty } \and

  \infer[New]
  { }
  {\Gamma \types \newExp : [\vv{x:A}] } \and

  \infer[Ind-1]
  {\Gamma \types e_1: \dictty}
  {\Gamma \types e_1[e_2]: \anyty} \and

  \infer[Ind-2]
  {\Gamma \types e_1: \listty \\ \Gamma \types e_2:\intty}
  {\Gamma \types e_1[e_2]: \anyty} \and

  \infer[Attr]
  {\Gamma \types e: [attr:A, \vv{x:A}] }
  {\Gamma \types e.attr : A}

  \infer[Call]
  {\Gamma \types e: \vv{B_1, \dots B_n} \to A \\
  (\forall i \in [1,n]) \,\, \Gamma \types e_i : B_i}
  {\Gamma \types e(\vv{e_1, \dots e_n}):A}

  \\\\\\\\
  \infer[Assign-Var]
  {\Gamma, x:A \types e:A}
  {\Gamma, x:A \types x = e \rhd \nonety}

  \infer[Assign-Attr]
  {\Gamma, x:[\vv{y:B}, attr:A] \types e:A}
  {\Gamma, x:[\vv{y:B}, attr:A] \types x.attr = e \rhd \nonety}

  \dots

  \infer[If]
  {\Gamma \types e: \boolty \\ \Gamma \types s_1 \rhd A \\
  \Gamma \types s_2 \rhd B}
  {\Gamma \types \ifStmt{e}{s_1}{s_2} \rhd \nonety} \and

  \infer[Return]
  {\Gamma \types e:A}
  {\Gamma \types \returnStmt e \rhd A} \and

  \infer[ExprStmt]
  {\Gamma \types e:A}
  {\Gamma \types e \rhd \nonety} \and

  \infer[Seq]
  {\Gamma \types s:B \\ \Gamma \types \vv{s}:A}
  {\Gamma \types s \, \vv{s} \,\rhd \,A}
  \\\\\\\\

  \infer[Decl]
  {\Gamma \types e:B  \\ \Gamma, x:B \types d_1 \rhd A}
  {\Gamma \types \varDecl{x}{e}{d_1} \rhd A} \and
  \infer[Fun]
  {
    \Gamma, x_1:A_i, \dots, x_n:A_n, f: \vv{A_1 \dots A_n} \to B  \types
    d_1 \rhd B \\
    \Gamma, f:\vv{A_1 \dots A_n} \to B \types d_2 \rhd A
  }
  {\Gamma \types \funDecl{f}{\vv{x_1, \dots, x_n}}{d_1}{d_2} \rhd A}

\end{mathpar}

\section{Examples}

To show how types (specifically the row types) flow around in the system,
consider the following program which we will call \(d_0\).

\[
  \begin{array}{l}
    d_0=\\
    \quad\mathsf{def} f(o,l):\\
    \quad\quad\quad o.length = l\\
    \quad\quad\quad \mathsf{if} \,\, l > \num{5} :\\
    \quad\quad\quad\quad\quad o.long = \true \\
    \quad\quad\quad \mathsf{else}:\\
    \quad\quad\quad\quad\quad \num{0}\\
    \quad\mathsf{in} \\
    \quad obj := \newExp \,\,\mathsf{in}\\
    \quad f(obj, \num{4}) \\
    \quad obj
  \end{array}
\]

We define a function f, which adds some attributes to the object that is passed
to it, and then call this on a fresh object. We are particularly interested
in what type(s) we can conclude for the object stored in (\(obj\)). First, we
will look at typing the body of \(f\).

\begin{mathpar}
  \Gamma_f = o:[length: \intty, long:\boolty], l:\intty
  \\\\
  \infer
  {
    \infer
    {\Gamma_f \types l: \intty}
    {\Gamma_f \types o.length = l}
    \\
    \infer
    {
      \infer
      {
        \infer
        { }
        {\Gamma_f \types l : \intty}
        \\
        \infer
        { }
        {\Gamma_f \types \num{5}:\intty}
      }
      {\Gamma_f \types l > \num{5}:\boolty}
      \\
      \infer
      {
        \infer
        { }
        {\Gamma_f \types \true : \boolty}
      }
      {\Gamma_f \types o.long = \true \rhd \nonety}
      \\
      \infer
      {
        \infer
        { }
        {\Gamma_f \types \num{0}:\intty }
      }
      {\Gamma_f \types \num{0} \rhd \nonety}
    }
    {\Gamma_f \types \ifStmt{l > \num{5}}{o.long=\true}{\num{0}} \rhd \nonety}
  }
  {\Gamma_f \types o.length = l;\, \ifStmt{l > \num{5}}{o.long=\true}{\num{0}}
  \rhd \nonety}
\end{mathpar}

Note that the assignments present in the body of the function force us to have
at least \(o:[length:\intty, long:\boolty]\) in the environment. The type
\(\intty\) for \(l\) isn't really necessary , and may not be retrieved by
inference, but for simplicity we have made this assumption here.

Using this typing for the body of \(f\), a typing for the whole program
can be concluded with the type of \(f\) taken into account.

\begin{mathpar}
  d_b = o.length = l;\, \ifStmt{l > \num{5}}{o.long=\true}{\num{0}}
  \\
  d_1 = \varDecl{obj}{\newExp}{f(obj, \num{4}); obj}

  \infer
  {
    \infer
    {
      \vdots
    }
    {o:[length:\intty, long:\boolty], l:\intty \types d_b \rhd \nonety}
    \\
    \infer
    { \vdots}
    {f : ([length:\intty, long:\boolty], \intty) \to \nonety
    \types : d_1 \rhd \nonety }
  }
  {\types d_0 \rhd \nonety}
\end{mathpar}
\\

This is pretty much just sequencing, the only thing to note is that we can
freely conclude any row type for \(\newExp\), it may not be immediately obvious
why we have chosen \(A_{obj}\) here.

\begin{mathpar}
  A_f =  ([length:\intty, long:\boolty], \intty) \to \nonety
  \\
  A_{obj} = [length:\intty, long:\boolty]
  \\
  \infer
  {
    \infer
    { }
    {f:A_f \types \newExp : A_{obj}}
    \\
    \infer
    {
      \infer
      {
        \vdots
      }
      {f:A_f, obj:A_{obj} \types f(obj, \num{4}) \rhd \nonety}
      \\
      \infer
      {
        \infer
        { }
        {f:A_f, obj:A_{obj} \types obj:A_{obj} }
      }
      {f:A_f, obj:A_{obj} \types obj \rhd \nonety}
    }
    {f:A_f, obj:A_{obj} \types f(obj, \num{4}); obj}
  }
  {f:A_f \types \varDecl{obj}{\newExp}{f(obj, \num{4}); obj}}
\end{mathpar}
\\\\

Looking at the typing of the function call \(f(obj, l)\) gives us some hints.

\[\infer
  {
    \infer
    {
      \infer
      { }
      {f:A_f, obj:A_{obj} \types f:A_f}
      \\
      \infer
      { }
      {f:A_f, obj:A_{obj} \types obj:A_{obj}}
      \\
      \infer
      { }
    {f:A_f, obj:A_{obj} \types \num{4}:\intty}}
    {f:A_f, obj:A_{obj} \types f(obj, \num{4}):\nonety}
  }
{f:A_f, obj:A_{obj} \types f(obj, \num{4}) \rhd \nonety}\]
\\
The type we obtained for \(f\) (which was forced by the attribute assignments
made in the body of \(f\)) forces us to use \(A_{obj}\) for \(obj\).
\\\\
Consider the following program:
\begin{mathpar}
  \begin{array}{l}
    \mathsf{def}\, f(x):\\
    \quad\quad x.foo = \num{0}\\
    \mathsf{in}\\
    o_1 := \newExp \,\, \mathsf{in} \\
    o_2 := \newExp \,\, \mathsf{in} \\
    o_1.bar = \true \\
    f(o_1) \\
    f(o_2) \\
  \end{array}
  \\
\end{mathpar}

The function \(f\) needs to have a type like \([foo:\intty] \to \nonety\)
based on its definition. In order for the call \(f(o_1)\) to be typable, we
end up needing the type \([foo:\intty, bar:\boolty] \to \nonety\) for \(f\),
and, because we later make the call \(f(o_2)\), this ends up forcing us to
give \(o_2\) the type \([foo:\intty, bar:\boolty]\). This isn't ideal, so it
seems like we want some sort of row polymorphism in our function types, maybe
we can give \(f\), a type like \(\forall r.[foo:\intty, r] \to \nonety\).
\\\\
